# Pocket Korean project notes

- This is a personal Android app in the PUBLIC `JustPixelll/pocket-lab` repository. Its six areas are Home, Learn, Write, Speak, Words, and Translate. They share local learning and character state; public source/releases do not make the user's notebook public.
- The visual and story direction is stylized fantasy at Greybridge Outpost: wayfarers, contracts, a recurring cast, and a contact codex. Use clear travel-equipment names and parchment, ink, forest, umber, and copper colors. Avoid childish character/shop copy.
- Learn contains exactly 10 story quests presented as contracts, with four challenges per quest. Preserve existing quest/lesson IDs and prerequisite progress when editing stories. Every quest includes Korean audio controls for its dialogue and learning material; completing a quest does not grant vocabulary mastery.
- Home uses Camp, Outfitter, and Equipment. Preserve existing cosmetic IDs, slots, styles, prices, free defaults, and equipped items when changing presentation. Cosmetics affect appearance only. Award 20 coins once per first quest completion and 10 coins once per first-ever green word. Quest replays and demotion/re-mastery must not award more coins. Preserve historical reward receipts, including past mastery followed by demotion, and credit eligible old progress once during migration.
- Never add romanized Korean vocabulary or romanized pronunciation. Korean sound hints use Hangul; TTS reads normal spelling.
- Keep dictionary forms separate from polite forms. Speech recognition checks recalled wording, not pronunciation quality.
- Preserve local vocabulary/review history and backup-merge compatibility. Schema 2 must continue reading schema 1 data and use the existing `pocketLabKorean.v1` storage key. Backups include the character, equipment, inventory, reward receipts, and purchase receipts alongside learning progress. Never reset storage to recover from parse/write errors.
- Keep rewards and purchases idempotent across repeated or older backup imports. Calculate coin balances from receipts; do not trust imported display totals. Retain purchases from both copies after a merge, keep spendable coins nonnegative, and account for any overlapping spending against future rewards. Catalogue IDs and prices are receipt contracts; changing them requires a migration or new IDs. Persist each mutation atomically before updating live state.
- Do not replace working native services with simulated results. Browser-only previews may clearly explain unavailable Android features.
- Model downloads must be initiated visibly. No keys or remote backend are needed for existing translation/ink features.
- Keep **Settings → Korean voice settings** available when Korean audio needs a voice. Guide users to choose a Korean-capable speech engine and install its voice data, then return without losing the quest. Translation/ink model downloads do not install a TTS voice. Microphone permission is for spoken input, not listening.
- Keep Google translation attribution beside results and in About.
- App update checks must be user-triggered native requests to the fixed public GitHub release endpoint. Open only the validated/fixed release or APK URL in the external system browser; do not add GitHub login, tokens, remote WebView content, or silent installation. Public release downloads need no sign-in.
- The user confirmed working native services on their actual v0.1.7 phone. Preserve that feedback as evidence for that installed prototype only; it is not a build/UI/device pass for later revisions. Validate changes with the smallest meaningful tests. `npm test` covers recall, status transitions, imports, curriculum prerequisites, one-time coin rewards, purchases, and migrations. The Android Actions build compiles and lints the native shell. Keep actual build, UI, and device results in `docs/verification.md`; do not infer phone-service success from browser mocks.
- Permanent signing setup remains an owner-run task through `scripts/setup-personal-updates.py`; detailed instructions live in `docs/personal-updates.md`. Do not inspect private key contents or put keys/passwords in repository files, release artifacts, issues, logs, or chat. The helper keeps the key outside the checkout and configures protected Actions secrets plus the public `POCKET_SIGNING_CERT_SHA256` variable. Do not claim setup is complete until it is verified.
- The current disposable prototype identity cannot support an in-place transition to the permanent signing key. Require one backup/export, uninstall, personal-release install, and import; then prepare the models again. Later releases with the same permanent identity can retain app data. Personal release publication is restricted to successful personal builds on `main` from a push or manual run; PRs and disposable debug builds must not publish.
